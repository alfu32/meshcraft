# Object-model examination and normalization proposal

This expands the original architecture audit in response to the user's request to eliminate redundancy. Source baseline remains `acd84f4c67509e10363c33850501eb8f4fc3ffa7`. Current behavior and file compatibility are requirements; the layout of Kotlin classes is not a required Rust layout. The proposal below is a design input for the early T46 gate, not an already implemented Rust model.

## Proposed normal form

Keep a small number of canonical concepts, with an explicit authoring/resolution boundary:

| Concept | Canonical fields | Excluded derived/session fields |
| --- | --- | --- |
| `Definition` | Stable ID, name, glue/edit profile, optional nonidentity definition frame, authored geometry-bundle ID, typed domain parameters, hotspot definitions, default child-layout ID, external-source metadata | Per-instance selection, resolved triangles, world bounds, cached matrices, runtime hotspots |
| `GeometryBundle` | Stable vertex records, segment endpoint IDs, triangle vertex IDs and RGBA, dimensions/text, local identities and unknown imported fields | Repeated full vertex vectors on every primitive, selected flags, GPU buffers, spatial indexes |
| `ChildLayout` | Ordered child-placement templates with stable template IDs, referenced definition, local transform and authored instance inputs | A cloned realized subtree for each parent occurrence |
| `Placement` / authored occurrence edits | Definition reference, local transform, hotspot/input overrides, optional actual geometry replacement/edit, optional child-layout override | Automatically materialized copies equal to the definition; computed world matrix |
| `OccurrenceRef` | Root placement and child-template path, with legacy instance-ID aliases as required | A pointer to a mutable copied GroupNode tree |
| `EditorSession` | Active occurrence and edit target (definition or instance), occurrence-aware selection, transient guides/tool draft/focus | Canonical geometry or persistent prototype copies |
| `ResolvedContent` | Cache keyed by definition/input/layout revisions; generated primitives, source attribution and resolved targets | A second independently editable document or mandatory saved copy |

This is a normalized graph of immutable/shared content plus explicit authored edits, not a requirement for a general ECS or a new B-rep kernel. Distinguish `None` (inherit) from an explicit empty replacement (intentionally remove all content). A single typed `InstanceEdits`/`GeometryBundle` representation replaces four loosely related nullable override stores.

Recommended resolve order: definition-authored geometry/domain generation → instance input/hotspot evaluation in source local space → authored occurrence overrides according to the recorded policy → placement/world transformation. Only allocate changed/generated content; return a shared definition bundle for a no-op instance. Preserve legacy ordering/selection by comparing C07/C15/C32 cases before freezing this rule.

Use one effective-content view for viewport, picking, snapping, export, explode, save snapshots and plugins. Consumers must not choose between a base store and an override by directly reading a node flag. Editing targets canonical owner IDs and operation services; generated sub-elements route to their source domain parameters or require an explicit explode operation.

## Geometry identity: remove coordinate copies carefully

The recommended candidate is a per-bundle vertex arena with stable VertexIds and indexed segments/triangles. Primitive types remain segments/triangles; a boundary-loop/half-edge migration is not implied. Shared vertices keep their identity when moved. Newly split topology emits an explicit identity remap consumed by selection/hotspots.

Legacy files lack a universal authoritative vertex graph. Do not weld every equal/near-equal position or every matching quantized key. Import must record primitive-slot/legacy vertex aliases, reuse identity only where existing semantics establish it, and preserve coincident independent geometry when identity is ambiguous. Coordinate coincidence can inform adjacency predicates without imposing the same edit identity. T46 compares indexed storage and a minimal alternative on real fixtures, measures overhead, and records the selected rule before T03 becomes fixed.

There is intentionally no global vertex table across unrelated definitions/contexts, no per-instance vertex table for a pure placement, and no positional hash used as an enduring vertex identity. Domain-generated vertices belong to their resolved source/revision and do not automatically become authored mesh vertices.

## Hierarchy and transforms: preserve the distinctions that matter

Observed transform equation is `W = parent_W × I × D`. Although D is identity in this corpus, imported nonidentity frames and definition-frame edits must still work. Collapsing I and D into a single saved placement is reversible only if D remains known or an explicit coordinate migration transforms geometry, annotations, domain parameters and hotspot/reference coordinates together. The initial recommendation retains optional semantic D and local I as affine values, with one derived world transform. No parallel editable axes/matrix/quaternion copies.

Shared child layouts need stable template IDs and occurrence addressing: the same nested child template can appear beneath several placed parents and still have independent per-occurrence input values. A bare child-template ID is not a unique realized instance ID. Preserve legacy instance IDs through aliases/migration metadata where clients or attachments use them.

Choose a common layout only after comparing child definition references, ordering, transforms and authored edits. The census checks nesting shapes only and cannot authorize merging differing transforms or hotspot state. Represent a genuinely different authored subtree as a layout override/variant. Defining a shared object must update its shared child-layout definition without overwriting unrelated per-occurrence edits. Parent lookup/reverse-definition usage are rebuildable indexes. Detect definition/layout cycles before resolution.

## Legacy import and export rules

1. Decode all sparse legacy DTOs losslessly; retain original IDs, unknown fields, references and authored-versus-generated ambiguity in compatibility metadata.
2. Import a nonempty instance override identical to its full definition geometry as inheritance only when the feature semantics and source attribution make that safe; retain the original serialized envelope for compatible export where needed. Do not blindly drop all snapshots with no hotspot position change: attachments, source versions or prior authored edits may differ.
3. Treat a differing override as meaningful until its origin is established. Preserve an opaque replacement or frozen fallback if the generating behavior is unavailable. Never regenerate over an unexplained authored difference.
4. Separate domain outputs from loose authored geometry using source attribution/semantic equivalence; both being present in a prototype does not mean all stored mesh is disposable. The legacy root has explicit filtering; other definitions need individual handling.
5. Build shared layouts and occurrence aliases without erasing different child transforms or inputs. A legacy fully expanded export can materialize hierarchy/geometry when required even if Rust's canonical document stores references.
6. Preserve schema-17 meanings/defaults through an IO adapter. New normalized storage does not justify assigning incompatible data under version 17. Older empty/absent override ambiguity is documented; explicit empty Rust edits remain representable.
7. Undo stores authored changes or shared immutable snapshots, not render caches or every no-op instance materialization. Discarding/rebuilding caches must leave save state, selection ownership and undo boundaries coherent.

## Gate before implementation contracts harden

T46 runs after T00's fixtures and before T02/T03 freeze geometry/identity/document contracts. Deliver an owner/lifetime/persistence table, selected schema sketches, reference/identity invariants, migration examples and measured comparison. Revisit T05/T16/T28–T34 against this decision; do not ask each feature agent to invent its own override model.

C32 verifies: an unchanged thousand-placement model shares source content; editing one definition updates shared occurrences; an instance hotspot changes only its occurrence; resetting inputs can return to shared content; explicit empty overrides remain distinct; differing legacy snapshots survive; nested child-layout changes and per-occurrence edits coexist; discarded caches change neither authored serialization nor undo; selection in one occurrence does not leak through shared stores; nonidentity frames and stable attachment IDs survive migration. Record actual memory/serialized-size measurements after implementation, without claiming savings from coordinate counts alone.

The plugin context in [plugins.md](plugins.md) deliberately uses stable IDs, occurrence references and the effective-content query service. It must not freeze the old redundant GroupNode representation into a public JavaScript API.
