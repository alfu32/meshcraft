# T11 handoff

Status: complete. T02, T03 and T10 are complete. This capsule records geometry snapping and the first guide-placement workflow.

The desktop viewport now returns construction-point snap candidates for Line, Rectangle, Grid Guide, and Axis Guide input. It considers endpoints, explicit segment midpoints and nearest points, hit-triangle edge midpoints and nearest points, ray hits on triangles, grid intersections, and grid lines on the nearest hit surface plane or, when no face is hit, the active perspective/orthographic construction plane. Candidate arbitration uses the legacy priority bands together with screen distance and camera depth; a front-surface depth pass prevents snapping to geometry occluded by a visible filled face. Model `snap_radius` is treated as physical pixels and converted to egui points at the active device scale. Candidate traversal covers transformed and nested occurrences; `SnapScope` restricts candidates to the active document, occurrence subtree or definition, while `SnapVisibility` filters hidden edges/faces and filled-face hits. World-space pointer requests for construction tools use the same snapping and click dispatch as GUI input. A colored ring marks non-free snaps, and completed Line operations report the snap kind.

The palette commands `view.grid_guide` and `view.axis_guide` activate one-click placement; G and T provide the legacy shortcuts. Guides use the picked surface normal, preview under the pointer, draw as construction overlays, and participate in grid/axis snapping. They are session state, separate from authored geometry, and clear when a new scene is installed. `view.guides.toggle` and the UI preference hide/show guide overlays and remove hidden guides from snapping; `view.guides.clear` removes all guides without changing document history. `view.guide.remove` activates a one-click tool that removes the nearest visible guide within ten logical pixels.

Permanent grid settings now include X/Y/Z normal selection and the reference 1–1000 step extent. The configured normal controls the perspective virtual construction plane and grid basis; orthographic construction planes remain view-aligned. Rendered grid lines downsample adaptively below 8 screen pixels per step while retaining major-line cadence. Existing saved preferences default to Y-up, and legacy `x_right`/`y_up`/`z_back` values remain readable. A temporary local grid cloud appears when a snap approaches the permanent grid edge, lies outside its extent or plane, or a grid guide exists. It follows the snapped surface normal, stays anchored within a seven-cell radius, and clears when snapping ends; it never changes the scene graph.

## Pixel radius and ground-control snapping — 0.23.1 (2026-10-22)

The native shell previously converted radius at the camera target, then imposed
`grid_size * 0.015` as a world-space minimum. A cylindrical query consequently
expanded/shrank the effective screen radius at other depths and at high zoom.
Native snap candidates are now accepted by their actual projected pixel distance.
BVH expansion uses each node/item's farthest depth; orthographic expansion stays
constant. Segment interpolation minimizes projected distance with perspective
correction. Existing endpoint/midpoint priorities, visibility, locking and
front-face occlusion checks are retained. The grid-size minimum is removed.

Free wall/slab controls exclude their own owner's geometry from snap queries.
Their fallback plane no longer becomes a fictitious face/grid for construction
helpers. Real geometry, ground-grid and guide candidates are considered first;
without a reference, movement is parallel to the active grid at the original
control elevation. If the ray is exactly parallel to that grid plane, a view-plane
fallback keeps the control draggable. Shift does not change that movement. Owner-only wireframe
previews and release-time transactions are retained. Elevated 3D reference points
remain available.
