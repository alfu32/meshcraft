# T11 handoff

Status: in progress. T02 and T03 are complete; T10's camera work is implemented but its full acceptance matrix remains open. This capsule records the initial snapping slice.

The desktop viewport now returns construction-point snap candidates for Line and Rectangle input. It considers endpoints, segment midpoints, closest points on segments, ray hits on triangles, and grid intersections on the nearest hit surface plane or, when no face is hit, the active perspective/orthographic construction plane. Candidate arbitration uses the legacy priority bands together with screen distance and camera depth. Model `snap_radius` is treated as physical pixels and converted to egui points at the active device scale. Candidate traversal covers transformed and nested occurrences; cached world bounds cull off-screen content. A colored ring marks non-free snaps, and completed Line operations report the snap kind.

Checks: `cargo fmt --all -- --check`, `cargo test --workspace` (78 core, 80 desktop library, 14 IO, 5 CLI), `cargo clippy --workspace --all-targets -- -D warnings`, `cargo check -p meshcraft-desktop --lib --target wasm32-unknown-unknown`, `python3 docs/rewrite/scripts/verify_plan.py`, and `git diff --check` pass. Snapping regressions cover transformed instance endpoints, midpoints, perspective segment points and face hits, an orthographic face hit, grid intersections, radius rejection, DPI-aware pointer mapping, and a Line tool commit that creates one undoable snapped segment.
