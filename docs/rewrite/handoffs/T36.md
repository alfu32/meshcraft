# T36 — Common geometry interchange

## 0.24.0 — Native mesh workflows (2026-10-22)

The 0.24.3 placement follow-up caches insertion wireframes and their native GPU upload;
pointer motion changes a transform rather than cloning and validating the model. See the
[dense-import interaction validation](interaction-performance-validation.md#import-placement-feedback--0243).

`meshcraft-io::mesh` implements bounded, headless OBJ, STL and ASCII DXF adapters.
OBJ accepts negative/slash indices, concave polygons, linework, RGB vertex colors
and local MTL diffuse/alpha. Exports include geometric normals and explicit lines.
STL auto detection uses the binary count/length rather than the misleading `solid`
header; `.stl`/`.stlb` output is binary and `.stla` is ASCII. DXF covers 3DFACE,
LINE, SOLID/TRACE, ordinary 2D/3D polylines and tessellated circles/arcs; unsupported
entities are diagnostic, rather than silently advertised as retained.

Native commands replace the deferred Import/Export entries, appear in the native File menu
and command palette, and are available through MCP. Import creates a named
prototype with minimum-corner insertion anchoring, then starts existing wireframe
placement. Supplying an automation `position` imports and inserts in one transaction.
Export uses the selection if nonempty, or `selection_only:false` for the full scene.
Occurrence transforms, current script frames, instance deformations, generated
architecture and dimension/leader linework are collected from the frozen document.
IFC additionally retains named occurrence chunks. Indexed selection membership
avoids repeatedly scanning the entire selection for each primitive.

Workers parse/decode/write, while the UI alone publishes transactions and files.
The import result checks document generation, revision and editing context. Cancel,
parse failure, invalid units, malformed geometry and stale imports preserve the model.
Export writes/flushes a sibling temporary file, then publishes by rename only after
completion and a final cancellation check. RAII removes unpublished files, including
when the application closes. Existing outputs survive failure/cancellation.

Physical export uses `unit_size` meters per internal coordinate, independently of
its display label. Preserve the filename unit convention (`part_mm.obj`), with
optional explicit unit and one additional coordinate scale. Imports honor embedded
unit metadata for DAE/AMF/DXF/IFC as a documented improvement over legacy parsers
that ignored it. 3MF is physical and glTF uses meters. See the
[complete subset and unit guide](../../interchange.md), also returned by
`interchange.formats` and embedded in MCP discovery documentation.

New adapters are pinned to pure-Rust gltf 1.4.1 (without image/network loading),
roxmltree 0.21.1 and zip 2.4.2 (only flate2-backed deflate). No native libraries,
network fetching or executables are added. ZIP APIs are used for bounded in-memory
entry reads/writes, never filesystem extraction or permission restoration. XML
preflight bounds attributes/namespaces and tag lengths before parsing, disallows
DTDs, and caps node count/depth. Local linked resources must remain beneath the
source directory, including after symlink resolution. Referenced-source reads and
all archive decompression have byte limits. This is boundary hardening, not a claim
that arbitrary hostile input has undergone a full security audit.

## Validation

See [T37/T38 subset qualification](T37.md). Automated checks cover hand-authored
independent OBJ/DXF examples, both STL encodings, unit conversions, concavity,
line-only scenes, transformed/selected occurrences, scripts/architecture, malformed
input, cancellation, output retention and single-Undo import transactions. Native
Linux/X11 checks and read-only legacy-file probe results are recorded alongside
these changes. Cross-platform native runtime qualification remains separate.
