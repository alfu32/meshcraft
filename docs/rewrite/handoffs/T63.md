# T63 — #30 Procedural materials, under #29

Status: **Complete** · Requirement P07 extension · Acceptance C42 · 0.34.0.

Source contract: [#29](https://github.com/alfu32/meshcraft/issues/29), scoped to
[procedural materials #30](https://github.com/alfu32/meshcraft/issues/30).
Procedural objects/tree/bush remain [#31](https://github.com/alfu32/meshcraft/issues/31).

## Implementation

- Shared core program resources and typed parameter declarations, including
  defaults, labels/descriptions, range/step/unit metadata and enum choices.
  Floats, signed/unsigned integers, seed, Boolean, vectors, RGBA, matrix and texture
  inputs resolve program defaults → material configuration → assignment values.
- Conventional `Material` gains optional procedural configuration and PBR base
  settings. Programs and material/assignment settings persist in the normal
  document, history, legacy-compatible project envelope and imported subscenes.
  Resource/material collisions remap references without overwriting the host.
  Architectural records retain assignment overrides through rebuilding and IO.
- Native OpenGL 3.3 instancing generates grass entirely in the vertex shader.
  The only uploaded source geometry is a triangle distribution domain. No blade
  vertices/faces enter `Document`, CPU picking/snapping, mesh export or Explode.
  Repeated instances share domain buffers; parameter changes update uniforms.
  Source-coordinate hashes and explicit seeds make regenerated IDs irrelevant.
- Grass parameters: density, height, width, curvature, seed, wind and color
  variation. Instanced source transforms, conservative expanded bounds, frustum
  rejection and distance-based density LOD apply before bounded GPU work.
  The material candidate budget caps each placement; custom surface programs
  deform/shade original triangles. Source geometry remains selectable/snappable.
- Opaque procedural passes precede translucent model/procedural passes. Generated
  opaque details cast/receive shadows. Optional conventional base references
  supply RGBA, texture dimensions and PBR roughness/metallic for GGX shading;
  ordinary materials retain their pre-existing viewport behavior.
- Custom programs declare GLSL vertex/fragment functions and rendering metadata;
  the editor does not expose graphics API control. Compiled programs, textures and
  domain buffers belong to the graphics worker and retire when unreferenced.
  Compile/link logs and unsupported-program/backend diagnostics reach the UI/MCP.
  Missing/unsupported/broken programs retain the source's conventional appearance.
- Materials UI adds New Grass, program selection, typed parameter controls, reset,
  Apply, selection override read/apply/reset, base reference, LOD/budget/bounds,
  PBR controls, and a monospace program metadata/vertex/fragment editor.
  Shader code is edited directly, without JSON string escaping. Save and Apply
  commit; Cancel/Escape discards unapplied edits. Program definitions use their
  own explicit Save action. Animation changes only renderer time/uniforms, and
  pauses when no animated procedural placement is visible.
- MCP publishes program declarations via `meshcraft_scene.proceduralPrograms`,
  and schemas/descriptions for `material.program`, `material.save`,
  `material.parameters`, `material.apply`, plus native capture diagnostics/counts.

## Boundaries

This delivery implements the portable vertex-instancing path, not compute/mesh
shaders. Unsupported backend declarations preserve data and show diagnostics;
advanced GPU mechanisms remain #29's later phase. Grass is a reference surface
material; independent procedural object types/tree/bush are #31. Generated details
are visual-only and do not bake/export/collide or become editable mesh elements.

The current material candidate budget is per placement, up to one million.
If a blade domain has more source triangles than its configured candidate budget,
no blades are emitted: increase the budget or use a simpler distribution surface.
Custom deformation authors declare conservative `boundsExpansion`; the renderer
cannot infer bounds from arbitrary shader source. Texture inputs accept file
paths (absolute, or relative to the process working directory), with a white
fallback and diagnostic when unavailable. General order-independent transparency
and physically based rendering for the conventional viewport are outside this
material-generation change. Alpha from a custom shader requires its program's
`transparent` flag for blending/depth-mask behavior.

## Validation

Validation on Linux X11/Xvfb/software Mesa, 2026-10-24:

- `cargo test -p meshcraft-core -p meshcraft-io -p meshcraft-desktop --locked --offline`:
  **732 passed** (309 core, 376 desktop library, five CLI, 42 IO), 13 opt-in
  probes ignored; documentation tests also pass.
- Two explicit real-OpenGL procedural checks pass: deterministic grass and
  seed/wind changes, retained domain buffer identity, actual packed shadow depth
  from generated blades alone, translucent-shadow exclusion, shader error
  fallback, custom texture uniforms, PBR output, shared placement domains,
  per-instance overrides, culling and idle pause. No CPU blade topology is added.
- Existing GPU buffer lifetime/selection/transform, line projection/near-plane
  clipping, shadow/composition and insertion-placement checks pass. Analytic
  ground-shadow intersection-over-union remains 0.919.
- Strict Clippy with all targets, native build (`Meshcraft 0.34.0`) and browser
  library check pass. Browser check has three pre-existing dead-code warnings;
  browser procedural rendering is not qualified. Formatting, diff/plan validation
  and eight release-helper tests pass.
- A private native GPUI session at 1500×1000, Xvfb `:96`, MCP port `18766`,
  used actual construction/assignment commands and world-point input. Two
  surfaces share grass but retain separate heights. Capture reports 3,318
  candidate instances/two procedural draws while authored geometry stays at eight
  edges/four triangles. Undo/Redo, async save/reopen, material draft cancellation,
  program draft cancellation, metadata/source editor layout and scroll access to
  Apply/Save/override controls pass. The session used only its own scratch files
  and settings. Wind advances renderer frames without document edits; returning
  wind to zero stops the refresh loop. See [evidence](../references/procedural-materials/validation.json).

  cargo test -p meshcraft-desktop --lib gpu_ --locked --offline -- \
  --ignored --test-threads=1 --nocapture
