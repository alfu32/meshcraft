# T60 — Integrate GPUI and raylib desktop while preserving headless commands (#21, #25)

Status: **In progress** · High priority · [GitHub issue #21](https://github.com/alfu32/meshcraft/issues/21)

## Objective

Make the qualified offscreen raylib 6 renderer and GPUI layout experiment the production desktop application. Keep the existing command IDs, JSON parameter schemas, model, transaction history, project IO and tool/session behavior authoritative. Route GPUI actions and viewport input into that same session; do not fork modeling behavior in the UI or renderer.

## Architecture and behavior

- GPUI owns menus, command palette, ribbon tabs/groups, tool palettes, inspectors, settings controls, focus and status. Populate controls from `MeshcraftApp::command_catalog()` and `native_toolbar_catalog()`; retain command IDs in element IDs and invoke `dispatch_command` with schema-valid payloads.
- Raylib owns a hidden offscreen context and `RenderTexture2D` on one worker thread. It publishes immutable BGRA/vertically corrected `RenderImage` frames through a latest-frame mailbox; GPUI presents each frame as a normal image so menus and panels remain above the canvas. Resize the target to the actual viewport pixel bounds.
- The shared session remains authoritative for click selection, left-to-right window selection, right-to-left crossing selection, connected/coplanar multi-click selection, snapping to geometry and grid, Escape, nested object editing, tool input, guides, cursor axes and construction/measurement feedback. Right-drag orbits around the camera target, Shift+right-drag pans, and the wheel zooms.
- Render document faces with distinct front/back tints and selection highlighting; include the existing tool previews, cursor, guides and text feedback in the viewport snapshot. Keep authored lines and overlays out of any later shadow-caster pass.
- Remove the retired Bevy renderer and dependency graph. Extract remaining egui/eframe types and UI-bound session code before removing eframe; preserve the command/session and project behavior through that refactor.

## Progress

- Started on branch `work` after checkpoint `099738c` (`docs(planning): start GPUI raylib production integration (#21)`).
- Switched `apps/desktop/src/main.rs` to the GPUI host and added the offscreen worker and viewport bridge in `apps/desktop/src/gpui_app.rs`.
- Wired scene snapshots, face/line rendering, selection highlighting, grid, construction guides, cursor axes and tool preview/feedback into raylib.
- Added command-backed menu, ribbon, palette, inspector and model/UI settings controls. Every command is reachable from its menu/ribbon/palette catalog; the command palette no longer truncates results. Viewport pointer events route through existing native snapping, picking, selection and tool APIs.
- Connected UI preference edits to `ui.update_preferences`; the renderer follows permanent-grid visibility, workplane normal and extent. Grid fallback snapping uses the configured workplane. Selector drags render blue window or green crossing feedback.
- Made the viewport worker event-driven: it renders after scene, camera or viewport changes, then waits on a condition variable. A low-cost GPUI frame watcher notifies the view only when the worker publishes a newer image. The idle smoke process dropped from about 57% CPU with continuous 60 Hz shell/canvas redraws to about 2% CPU with no repeated idle renders.
- Reversed vertical camera drag while preserving horizontal yaw; right-drag orbits around the target and Shift+right-drag pans it. Added regression tests for camera drag direction and for suppressing redundant redraws when camera/layout state is unchanged.
- Classified `hotspot.begin_placement` in the Point Construction palette, alongside its Tools menu entry, per issue #25.
- Removed the production Bevy module and Bevy dependencies. `eframe` is still required because `MeshcraftApp` and its interaction adapters use egui types; full framework extraction remains outstanding.
- `cargo fmt --all`, `cargo check -p meshcraft-desktop --bin meshcraft`, and `cargo test -p meshcraft-desktop --lib` pass (226 tests). The live desktop smoke run confirms startup and low idle CPU. Manual input, target resize/DPI, menu stacking and shutdown checks remain with the user; the task stays in progress until those checks and remaining egui/eframe extraction are complete.
