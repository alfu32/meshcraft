# T60 — Retire Bevy/egui desktop implementation

Status: **Planned**. This cutover follows the GPUI + raylib-rs integration proof in [T59](T59.md). The accepted architecture and interaction contract are in [ADR-06](../../decisions/ADR-06-gpui-raylib.md) and [the viewport/UI specification](../../UI-3D_renderer.md); track implementation under [issue #21](https://github.com/alfu32/meshcraft/issues/21).

## Scope

- Extract command dispatch, tool/session state, transactions and non-visual selection behavior into a headless session API. Keep command IDs and JSON definitions independent of the UI and renderer; route native dialogs and file actions through typed host effects.
- Implement the GPUI shell (menus, grouped ribbon, command palette, inspector/settings and status) and embedded raylib viewport against shared session/document contracts.
- Preserve selection-driven operations on mesh entities and object instances, click/window selection direction rules, connected/coplanar multi-click selection, snapping, Escape behavior, nested prototype editing, planar construction, 3D modification and linear/planar/spatial/rotational/helical arrays.
- Port two-sided face shading, batched geometry, solid-geometry shadow maps, cursor/guides and text feedback. Keep grid, authored lines, selection and preview overlays out of the shadow-caster pass.
- Remove Bevy, bevy_ecs, bevy_egui, egui/eframe and their renderer/UI modules only after replacement paths exist; remove obsolete stack experiments and lockfile entries.

## Acceptance and evidence

Run core, IO and headless command tests, then verify C39/C40/C41. Replay the two local recordings in the dense-array stress workflow; the MP4s are intentionally ignored and must not be staged. Record the platform/display backend, exact dependency revisions and commands, resize/focus/input results, p50/p95 pointer-feedback timing and any unsupported platforms. Do not claim success from compilation alone or use continuous GPU-to-CPU framebuffer readback in production.

No implementation or validation for T60 is claimed yet. T59 must first prove the native viewport integration and synchronization boundary.
