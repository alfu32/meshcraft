# T60 — Integrate GPUI and raylib desktop while preserving headless commands (#21, #25)

Status: **In progress** · High priority · [GitHub issue #21](https://github.com/alfu32/meshcraft/issues/21)

## Objective

Make the qualified offscreen raylib 6 renderer and GPUI layout experiment the production desktop application. Keep the existing command IDs, JSON parameter schemas, model, transaction history, project IO and tool/session behavior authoritative. Route GPUI actions and viewport input into that same session; do not fork modeling behavior in the UI or renderer.

## Architecture and behavior

- GPUI owns menus, command palette, ribbon tabs/groups, tool palettes, inspectors, settings controls, focus and status. Preserve the layout functions and control lists copied from tag `0.2.0` in `apps/desktop/src/gpui_layout.rs`. Bind supported controls to `MeshcraftApp::command_catalog()` through stable control keys; leave unfinished controls visibly disabled. Keep command/session behavior authoritative.
- Raylib owns a hidden offscreen context and `RenderTexture2D` on one worker thread. It publishes immutable BGRA/vertically corrected `RenderImage` frames through a latest-frame mailbox; GPUI presents each frame as a normal image so menus and panels remain above the canvas. Resize the target to the actual viewport pixel bounds.
- The shared session remains authoritative for click selection, left-to-right window selection, right-to-left crossing selection, connected/coplanar multi-click selection, snapping to geometry and grid, Escape, nested object editing, tool input, guides, cursor axes and construction/measurement feedback. Right-drag orbits around the camera target, Shift+right-drag pans, and the wheel zooms.
- Render document faces with distinct front/back tints and selection highlighting; include the existing tool previews, cursor, guides and text feedback in the viewport snapshot. Keep authored lines and overlays out of any later shadow-caster pass.
- Remove the retired Bevy renderer and dependency graph. Extract remaining egui/eframe types and UI-bound session code before removing eframe; preserve the command/session and project behavior through that refactor.

## GPU frame lifetime and overlay refinement — 2026-10-20 (#18, #21)

The production canvas now explicitly evicts retired `RenderImage` entries through GPUI's `Window::drop_image`. Releasing the CPU `Arc` alone did not remove the old image's GPU atlas allocation. Only the presented frame is retained by the canvas; repeated painting reuses its existing entry. Canvas release evicts the last image, and the detached watcher exits when its weak canvas handle expires.

The kernel journal at 00:58:17 records a global OOM: rust-analyzer was killed, the terminal cgroup peaked at 27.8 GB, and system shared memory was approximately 24 GB. That identifies the killed process and memory pressure, not a sole culprit. The viewport atlas leak was independently reproduced and fixed. No unrelated user/editor processes or system memory settings were changed.

Controlled Xvfb/software-Vulkan test, 1280×800 blank scene, moving the pointer every 60 ms:
