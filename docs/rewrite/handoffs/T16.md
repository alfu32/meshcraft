# T16 — Reusable objects, placement and explode

Status: in progress. T12, T15 and T46 dependencies are complete.

Implemented selection-first grouping for object occurrences and supported mesh selections, parent-local nested duplication, one-pick definition placement with optional surface alignment, mesh-only explode/materialization with result selection, and deletion of unused definitions. Desktop commands include `object.create_from_selection`, `object.place_selected_definition`, `object.toggle_place_glue`, `object.explode_selection` and `object.delete_unused_definition`. Core APIs are in `operations::objects`; placement state is in `tools::object_place`.

Shared interaction rules remain explicit: click selection can target objects and typed mesh entities; left-to-right screen windows require full containment, while right-to-left crossing windows include intersections. Escape clears a nonempty selection, otherwise clears guides, and always cancels the active tool and returns to Select. Every active point-input tool uses the shared snap resolver for grid and existing geometry, including transform and object-placement picks; Cuboid base/elevation picks consume snapped coordinates.

Validation: `cargo test --workspace` passes (120 core, 131 desktop library, 14 IO, 5 CLI); `cargo clippy --workspace --all-targets -- -D warnings`, formatting, `git diff --check` and `verify_plan.py` pass.

Remaining: explode currently supports mesh-only content and rejects domain data or instance edits without adapters. Selected dimensions, text, hotspots and other domain payloads still need typed grouping/copy/explode adapters. Complete C08 mixed-payload lifecycle coverage and C32 normalized/effective-content equivalence before marking T16 complete.
