# T58 — egui shell with custom Bevy viewport

Status: **In progress, high priority** for [issue #20](https://github.com/alfu32/meshcraft/issues/20). This replaces the rejected Bevy UI scope in T57. The user authorizes selectively copying/adapting components from [CADCraft](https://github.com/storytold/cadcraft) and [SolidCraft](https://github.com/tangency-labs/solidcraft).

## Architecture contract

Use egui for the application shell through `bevy_egui` in the Bevy 0.20 native app; pin the compatible integration after a one-window compatibility spike. Bevy retains the custom GPU-rendered viewport, camera, object-model interaction, selection, snapping, guides and previews. The egui central content rectangle sets the Bevy camera viewport in physical pixels, and egui capture state owns pointer/keyboard events over controls. Keep one window/event loop and shared, UI-independent document, command, selection, tool, undo, persistence and preference services. Do not return to CPU geometry projection or keep parallel UI shells.

The full functional specification and framework evidence are in [ADR-05](../../decisions/ADR-05-ui-architecture.md); acceptance is [C40](../acceptance.md#c40--egui-shell-with-custom-bevy-model-viewport-20), with C17/C23/C26/C39 retained.

## Acceptance and checks

The target visual hierarchy follows the user's references: SolidCraft's textual top menu and tabbed ribbon, a central Bevy viewport, and a persistent right-side selection/settings inspector. Ctrl+Shift+P uses a CADCraft-style searchable command completion window. Existing command IDs, availability states and parameter schemas are the source for menu actions, palette results and settings forms. New documents remain empty; an empty scene must still show the complete shell, setting values and clear no-selection/no-object text.

The compatibility spike must verify egui render ordering above Bevy, viewport bounds/projection at resize and DPI changes, event ownership, editable controls and reactive idle behavior. The full migration preserves menu/toolbar/palette command parity and demonstrates create, click/window select, transform, snapping, nested object editing, setting edits, Escape and save/reopen. Add real input/focus tests and visual review across supported window sizes. Record UI frame cost independently from Bevy rendering, idle CPU and click-to-visible selection. Repeat the T00/#18 2,000-entity frame, hover, pick and edit measurements before claiming a performance improvement.

## Implementation progress

The native integration uses `bevy_egui = 0.43.1` with Bevy 0.20 and now renders the existing desktop workspace from `app.rs` inside `EguiPrimaryContextPass`: top menus, tabbed command ribbon, right inspector/settings, command palette and status row. A dedicated full-window transparent 2D camera owns the primary egui context; this prevents the 3D camera's smaller viewport from clipping the UI screen bounds. The central area allocates the Bevy model viewport, and the 3D camera tracks that rectangle in physical pixels using egui's effective pixels-per-point. Viewport hit tests convert window cursor coordinates through egui zoom so UI scaling keeps picking aligned. The legacy Bevy chrome is hidden, and its duplicate palette handlers are no longer scheduled. egui visuals are initialized once instead of mutating the style on every pass. Empty documents skip the shadow-map pass; shadow maps turn on for visible mesh faces and respect the user's CSM setting. Cargo's dev profile optimizes dependencies for interactive testing. The focused and unfocused Winit loops now wait indefinitely for input; a small timer thread wakes the event loop only for a finite repaint delay reported by egui, replacing the desktop preset's five-second idle redraw. The timer is cancelled when egui reports no pending repaint and shuts down with its resource. eframe is pinned to egui 0.36 to share the exact widget/context types with `bevy_egui`; the two separate UI implementations are no longer drawn. Regression tests cover full-window output, scaled viewport mapping, zoom-aware hit tests, empty-scene shadow suppression, repaint-delay extraction, and timer wake/cancellation.

The user's screenshots exposed the root cause: egui's primary context was attached to the 3D camera, so bevy_egui used the small model viewport as the UI screen rectangle and clipped the shell. A dedicated full-window 2D context camera now separates UI bounds from the 3D camera viewport. A live compositor screenshot after rebuilding is still needed. Until visual review verifies the full window, DPI/resize mapping, menu input and click-through to the viewport, T58 remains in progress. Actual UI/viewport frame-time and pointer-latency measurements on the target GPU, idle CPU after event-driven wake scheduling, the candidate-project component audit and full command/settings parity remain open. The lockfile unifies eframe and `bevy_egui` on egui 0.36; wasm binding versions remain aligned to the Bevy-compatible dependency floor (`js-sys >=0.3.104`).
