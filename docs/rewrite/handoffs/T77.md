# T77 — Textured materials and the texture edit mode

Status: **Complete**, 0.55.0 · C50. Spec: [Textures](../spec/materials.md#textures-t77).

## Delivered

- **Model.** `Material` gains `textureOffsetU/V` and `textureTint` (0 to 1), omitted from files when zero, so older
  projects read and write unchanged. `texture_mapping.rs` defines the planar mapping once: each face projects onto its
  own plane in its prototype's space, U to the right as the face is seen, V up it, X for U on horizontal faces.
- **Rendering.** Faces whose material has an image draw in their own batch per material, with the image bound and the
  placement passed as uniforms, so dragging a placement never rebuilds a mesh. `scene.fs` evaluates the same mapping
  from prototype-space positions, which `mesh.vs` gets from a fifth per-instance attribute. Images decode on a
  background thread, shrink to 4096 pixels at most and upload with mipmaps, repeat wrapping and 4× anisotropy. Until
  then, or if the file is unreadable, faces show the material color and the Materials panel names the file.
- **Material Editor.** The texture path is a file input: Browse opens the system file dialog Open and Save use,
  filtered to images, and stores a file beside the project relative to it. Width × height and a colorization field
  follow it. Procedural `texture` parameters use the same input.
- **Edit Texture Position** (`material.edit_texture`, Materials menu and panel). Click a textured face, then drag a
  corner or the middle of the outlined tile. Releasing saves to the material in one undoable edit. Escape cancels a
  drag, then ends the mode. `k3d_status.textureEdit` reports the mode and the tile's corners.
- `material.edit` accepts an `id`, so automation can open a given material.
- A command icon (an image tile with corner handles) and a stress recipe that performs a real corner drag through
  the native pointer.

## Validation

Run on the 0.55.0 tree:

- `cargo fmt --all --check`: passes.
- `cargo test --workspace --locked`: 837 passed, 22 ignored.
- `cargo clippy --workspace --all-targets --locked -- -D warnings`: clean.
- `verify_plan.py`: valid. `export_tool_inventory.py --check`, `design_tool_icons.py --check`, the icon, stress and
  `scripts/video` unit tests: pass.
- New tests: four mapping tests in `texture_mapping.rs` (axes, tiling, corner and middle drags, offset wrapping),
  stored and resolved paths and image decoding in `gpui_textures.rs`, and ray picking in `gpui_texture_edit.rs`.
- Native, `python3 scripts/verify_textures.py`: 11 of 11 checks. Pixels sampled from the window show the test image
  upright with its lower-left quadrant at the face's lower left. A click outlines the tile at exactly the face's
  corners. A corner drag sets the material to 1 × 1 with the opposite corner fixed, and the box shows the smaller
  tiles. A middle drag moves the offset by a quarter unit without resizing. Each Undo restores one drag, and Escape
  removes the outline. Evidence: [textures](../references/textures/).
- Stress, `run.py --tiers small medium --samples 1 --only material.edit_texture material.apply`: all passed.
- Frames reviewed: the textured box, the outline with its handles, the box after the corner drag (side and top faces
  follow too) and the Material Editor with its preview.

## Not verified

- The file dialog itself: the Xvfb harness has no desktop portal. Browse is the same `rfd` dialog as Open.
- Textures on Windows and macOS drivers, and anisotropic filtering where the extension is missing (raylib skips it).

## Known limits

- One mapping per material: a face cannot have its own placement, and there is no rotation yet.
- Cutouts do not cut shadows, and the grey tint marking externally referenced objects does not show on textured faces.
- Projected per face, so tiles do not run continuously around a corner between two walls.
- Images are referenced, not embedded: moving a project needs its relative images moved with it.
- Script `Material` values still render their color only, and interchange export omits textures (it says so).
