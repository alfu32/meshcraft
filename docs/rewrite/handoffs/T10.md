# T10 handoff

Status: complete. Orbit and restored camera poses support the requested ±89° pitch range, with a one-degree margin from the singular poles. C09 project/unproject/navigation coverage now includes the actual Desktop Menus and Buttons workspace layouts, multiple viewport sizes, native DPI scales and all six orthographic views.

`Viewport` now has a perspective orbit camera with target, orbit distance, camera-space pan, cursor-anchored wheel zoom, and target-centered fit-to-document. Ground-plane mapping unprojects a camera ray. Camera near/far planes and field of view are restored from schema-17 `cameraState`; save writes the perspective pose and projection values while preserving unknown camera fields. The persistence snapshot does not mutate document revision or undo state. Reopening restores the saved pose instead of framing over it. Near/far geometry is excluded from drawing and picking. Six orthographic bases retain constant screen scale along camera depth; the same projection drives rendering, depth ordering, fit-to-document, and pixel-space picking. Six `view.ortho.*` commands switch views and expose checked state without mutating the document. The legacy orthographic command selects top view; Orbit returns to perspective and reset restores the default perspective pose.

`view.camera.walkthrough` now activates the perspective walkthrough camera. WASD moves on the horizontal plane, Left/Right strafe, Up/Down adjust eye offset, Space jumps, right-drag looks, middle/Shift-right drag pans, and wheel moves along the view direction. Support height uses the highest mesh triangle below the camera, with the legacy ground-at-zero fallback. The Model Settings panel exposes the four legacy tuning defaults (24, 16, 48, 8) as validated application preferences. Walk camera movement remains session state; schema-17 saves retain the model perspective pose.

Line and Rectangle map orthographic pointers onto the active view plane through the origin, matching the legacy snapper's edge-on ground-plane fallback. Rectangle persists a planar face with view-consistent winding. Cuboid retains its ground-plane footprint and reports side-view construction as unsupported. Perspective construction uses the Y=0 plane; walkthrough uses its active camera ray. Height entry is rejected when the active projection cannot show vertical height.

Mapping regressions round-trip perspective ground picking and each orthographic construction plane across compact, panel-offset, and wide viewport rectangles; the app-level regression verifies world-point mapping through the actual Desktop Menus and Buttons layouts, and a T07 test covers native DPI scales of 1, 1.5, and 2. Core tests cover planar mesh creation and camera persistence.

## Visible native camera target — 0.24.1 (2026-10-22)

The GPUI/raylib viewport now draws a 2 × 2 × 2 internal-unit cross centered on the active camera
target, with red/green/blue world-axis strokes and a light outline. A final depth-independent
helper pass keeps it visible inside solids without adding model, selection, snap or export
entities. Each axis extends one model unit either side of the target; only stroke thickness
uses pixels. Perspective, orthographic and walkthrough share this rendering path.

Native Linux/X11 checks captured an empty perspective view, a target inside a 6-unit opaque
cuboid, a translated target and orthographic/top views. In top view, the 2-unit cross spans one
third of the 6-unit cuboid edge. [Viewport capture](../references/camera-target/inside-solid.png).
Windows and macOS runtime checks were not performed for this change.

display-dependent GPU test is ignored). `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo build -p meshcraft-desktop --bin meshcraft`, `cargo fmt --all -- --check`,
