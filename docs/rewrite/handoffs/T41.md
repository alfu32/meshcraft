# T41 — Native MCP implementation

## Implemented in 0.13

The desktop owns a stopped-by-default loopback server with persisted port and Start/Stop/Restart
in the MCP Server accordion. `mcp.rs` uses existing locked httparse/socket2 packages for bounded
HTTP framing/listening; the UI request queue owns all model work. JSON-RPC discovery advertises
only supported tools/resources, legacy initialization and modern per-request metadata. Modern
headers/body metadata are validated; JSON results, notification acknowledgement, origin/host
checks, body/queue/connection/deadline limits and explicit cancellation/close behavior are covered.

The live command catalog includes typed schemas and enabled/disabled reasons. Commands use the
same dispatch/undo path and native camera effects as buttons. Exact occurrence/entity targets,
world picks, geometry/material/settings/prototype queries, script source CRUD, job completion,
script errors and bounded request logs support agents without prior project knowledge. Stable
large primitive IDs are published as strings. Shared `script_api.rs` supplies editor completion
and MCP documentation; no duplicated API list is maintained. The embedded [guide](../../mcp.md)
contains coordinates, ownership, lifecycle and working construction/scripting examples.

## Scope still tracked

The original T41 acceptance also covers complete legacy REST aliases and the retained old scenario
fixture matrix; full old HTTP compatibility is not claimed. Groovy console
remains unavailable and is not advertised. One-shot JavaScript execution and viewport capture are implemented below.

## Validation

Six focused protocol/transport/model tests pass: version negotiation, modern metadata errors,
discovery, notifications, tool error shapes, chunked HTTP, browser-origin rejection, same-port
restart, request cancellation after disconnect, and live command/pick/query/select/delete/undo
plus script CRUD. Native panel and end-to-end client checks follow before the final handoff.


Checkpoint validation: `cargo test --workspace --locked` passes **534 tests** (238 core,
276 desktop, 5 CLI, 15 IO; two opt-in GPU probes excluded). Strict workspace/all-targets Clippy,
native build, plan verification and whitespace checks pass. A real HTTP client against an
isolated Xvfb app passed 19 discovery/model/selection/undo/camera/resource checks, discovered
89 shared SDK entries, and verified the native Start/Stop/Restart controls on port 8766.
[Native server panel](../references/mcp/server-panel.png). No host user scene was used or saved.


## 0.14 — One-shot scripts and agent feedback

`meshcraft_run_script` accepts a hook body or unified module, optional JSON instance properties,
name/world offset and commit/evaluate-only choice. One background process uses the exact existing
SDK and immutable model facade. The tool returns a job ID immediately. Completion bakes validated
geometry/hotspots into a static object in the active context, selects it and commits one undo
transaction. No continuing script is installed. Revision/generation/context guards prevent stale
output from committing. Failures, cancel, Stop/Restart and close cannot publish late geometry;
one current job, 128 retained summaries, property/diagnostic/log length bounds keep storage bounded.

`meshcraft_capture_view` returns PNG image content with frame/revision metadata. BGRA is converted
to RGBA, and a render request revision distinguishes fresh frames from an older readback. Read-only
MCP queries no longer republish unchanged scenes, so agents can poll without forcing redraws.
`meshcraft_resolve_document` exposes existing explicit save/discard/cancel replacement choices;
file operations need paths instead of opening OS dialogs. Concurrent clients may reuse JSON-RPC
counter IDs without rejecting each other. The Settings ribbon now links directly to the panel.

Native HTTP evidence: `python3 target/ci-debug/native-finish/mcp_script_probe.py` against the
isolated Xvfb app passed evaluate-only mode, SDK model queries/custom properties, a colored
12-triangle/12-segment object plus one hotspot, one-step undo/redo, a bounded infinite-loop error,
explicit cancellation with a responsive server, pending-document cancellation, fresh PNG capture
and asynchronous project save. Only temporary copies under target/ were opened/written. The
[PNG returned to the agent](../references/mcp/agent-view.png) shows the generated blue object;
the [native panel](../references/mcp/server-panel.png) shows the live controls and endpoint.

Standard tests additionally cover model/SDK parity, static baking/hotspots, stale/failed/canceled
results, oversized retained properties/errors, document choices, concurrent request IDs and image
content versus structured metadata. Final checks: `cargo test --workspace --locked` passes **541 tests** (238 core, 283 desktop,
5 CLI, 15 IO), with two opt-in GPU probes excluded. Strict workspace/all-targets Clippy,
native binary build, `cargo fmt --all`, plan verification and `git diff --check` pass.
Native HTTP checks cover legacy initialization and modern discovery, tools/call and resources/read.
The current app reports version 0.14.0; JavaScript/native rendering is locally verified on Linux.
Broader native platform/runtime qualification remains as documented by the existing SDK guide.


Final live rerun also verified omitted oversized property summaries, clipped diagnostics, explicit
scene-root roles, and modern tools/resources calls. Each queued mutation publishes its scene
before acknowledgement/next request; host-job completions synchronize the cached scene before
capture checks. This closes the capture/commit ordering race without redrawing on read-only polls.
