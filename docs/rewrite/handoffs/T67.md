Status: **Complete**, 0.38.0 · P03/P07 · C03/C22/C42.

## Delivered

- Activate Stair from the Architecture menu/ribbon/toolbar. Pick a closed planar
  contour C, then an open walking path P. Accept complete object instances with
  nested linework, or connected selected segments. A preselected contour starts
  the second stage. Inspector buttons capture separate selections; Select/Window
  can change selection between captures. Escape cancels without a model edit.
  Retain sources and respect path direction, placement transforms and edit scope.
- Store a canonical `architectureStairs` owner, rather than a generated object
  prototype. Partition the contour through a conforming walking-progress field;
  step regions cannot overlap at turns. Generate consistently oriented closed
  tread/support geometry, including straight, L/U and sampled curved flights.
  Reconcile vertical mesh junctions. Straight affine flights avoid unnecessary
  walking-station subdivision (the regression bounds a 14-step shell below 400
  triangles). Explicit limits reject oversized/invalid inputs atomically.
- New height is 10, steps 14, support thickness 0.2. The Stairs inspector edits
  these plus independent left/right guardrail guides, spacing (default 1) and
  levels (default 5). Copy upper side outlines and riser transitions at offsets
  spacing × 1..N; zero levels hides guides. Guides remain segments, not rail solids.
- One selected stair exposes a triangular height control. Reuse the existing
  owner-only phantom wireframe, up-axis constraint, single release transaction
  and Escape cancellation. Numerical edits apply to matching selected stairs.
  Count the semantic owner once, including its actual managed edges/faces.
- Integrate surface materials/procedural overrides, clipboard, move/rotate/copy,
  explode and canonical save/load/regeneration. Explode directly materializes
  ordinary geometry/guide segments. Persist legacy bounds/walking endpoints;
  preserve stored heights and the old four guide levels when omitted in old data.
- Fix architectural material assignment in two places. The inspector already sent
  material IDs, but the command schema omitted seven wall/slab/frame ID arguments;
  the dispatcher rejected them and reloaded the old bindings. Register every ID
  field (including stair slots), publish them through MCP and retain failed drafts.
  The Materials manager also used persisted record IDs as model identities. After
  legacy reopen these differ; use the selected semantic owner ID. Add correct
  tread/support slots to the general assignment path.

## Limits

Inputs are one closed planar contour and one open coplanar walking path. Source
geometry is captured at creation; later source edits do not automatically regenerate
an existing stair. Guides are linework. Stair height/profile geometry respects its
stored up axis; arbitrary skew/nonuniform planar transforms require Explode.
Live UI/GPU qualification covers Linux x86_64 software Mesa. Windows/macOS and
hardware GPU drivers require native qualification. T30 remains the aggregate
legacy/source qualification task, with its requested stair slice delivered here.
