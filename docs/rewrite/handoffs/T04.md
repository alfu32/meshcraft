# T04 handoff

Status: complete; T03 is complete.

- Added `transactions::PendingTransaction` with validated staging, preview, commit, and cancel boundaries. Failed stages and stale commits do not publish partial edits.
- `TransactionHistory` provides one `ChangeSet` per explicit commit, redo branching, labels, timestamps, monotonic restore revisions, and 20-operation / 64 MiB limits. Camera, lighting/shadow controls, application preferences, and selection stay outside native authored history; model settings are included.
- Imported legacy history remains byte-for-byte opaque until traversed. The desktop decodes snapshots only as Undo/Redo reaches them, honors the filtered legacy active index, and connects supported states to the same bounded timeline as new edits. It skips corrupt neighboring snapshots with diagnostics; pruning retains the nearest states.
- Added reopen-with-history coverage for edit → undo native edit → undo/redo legacy state → redo edit.

Checks: `cargo fmt --all --check`, `cargo test --workspace` (59 core, 16 desktop, 6 IO), workspace Clippy with warnings denied, desktop WASM check, `verify_plan.py`, and `git diff --check` pass.

Changed paths: core transactions, desktop startup and Undo/Redo commands, T04/T05 handoffs and task registry, and the F08 history policy.

Limits: imported snapshots are supported only when they match the current importer’s prototype/instance shape. Legacy camera and lighting values are not applied to runtime controls during replay; broader schema support remains in T05.
