# T62 — Scripted prototype hooks and preview IDE

Status: **In progress (native platform qualification remains)** · P08 · C43 · 0.7.1.

Implemented object configuration as prototype metadata, alongside authored geometry
and nested instances. `onCreate` initializes serializable per-instance properties;
`onAnimationFrame` emits bounded drawable arrays. The JavaScriptCore SDK supplies
Point/Color/Material, line/face/hotspot and primitive helpers. Graphically authored
geometry is exposed through `this.geometry`. Model queries are immutable snapshots.
Copies preserve instance state and hotspot overrides; Explode materializes current
output, retaining colors/material metadata without adding another scripted object.
Project IO preserves sources and instance state; derived frames remain transient.

The GPUI mini IDE has one monospace JavaScript editor with Ctrl+Space API/help completion, Save/Preview/Cancel, diagnostics
and an independently navigable preview. Preview rendering shares the existing
raylib context and presents a normal GPUI image. Draft evaluation stays isolated
from the source model. Errors retain the last valid output and source/model edits
permit retry. Worker processes have execution/output limits and Linux RSS checks.
The JavaScriptCore library remains resident until helper-process exit because its
GC/JIT threads outlive individual contexts.

Validation: `cargo test --workspace --locked --offline` passes 510 regular tests
(233 core, 257 desktop, 15 IO, five CLI; two opt-in probes ignored). Strict
Clippy, native build, formatting, eight packaging tests and the plan verifier
pass. Tests exercise unified hooks/shared helpers, legacy hook bodies,
immutable queries, primitive generation, interruption, invalid output, material
metadata, authored hotspot baking, per-instance state/copy, legacy persistence and current-output Explode.

Worker probes evaluated 120 cube/hotspot frames in 1.292 s; helper RSS grew from
34,324 to 36,764 KiB and stayed within that measured bound. Infinite-loop and
exception requests followed by valid geometry succeeded in the same helper.
Ubuntu 18.04's JavaScriptCoreGTK 2.32.4 exports both interruption functions. These
are bounded local probes, not broad performance/platform qualification.

An isolated Xvfb/software-GPU run opened the editor, changed initializer values,
previewed and saved generated geometry, navigated its preview, and dragged a
scripted instance hotspot. The final GUI pass verified the unified monospace editor, Ctrl+Space opening at
the cursor, `model.` filtering, Arrow/Enter insertion, Escape dismissal and the
working preview. [Unified editor/API](../references/scripted-objects/unified-api.png),
[model API help](../references/scripted-objects/model-api.png),
[keyboard completion insertion](../references/scripted-objects/completion-inserted.png). A running-image
worker launch fix also keeps an open Linux UI usable after Cargo replaces its
executable during development. Static generated geometry no longer forces repeated
rendering when only instance properties change.

Linux implementation is locally exercised. macOS framework live qualification,
Windows JavaScriptCore redistribution and other native-platform checks remain
open; see [SDK/runtime contract](../spec/scripted-objects.md). No alternate engine
or automatic runtime download is introduced. T47–T50 plugin-manager scope remains
separate from these object hooks.

## 0.7.1 — Scripted instance scaling regression

The old evaluator cloned, transmitted, compiled and froze the entire scene per
instance, then abandoned its loop after two seconds and restarted at the first
occurrence on the next request. Late occurrences could remain stale indefinitely.
The runtime now sends one buffered query snapshot per sweep and lazily parses it
only for actual model queries. Requests are JSON data rather than embedded script
source; the shared SDK string lets JavaScriptCore reuse compilation work. A VM is
shared within a sweep, with fresh globals for each invocation. Instance state and
model immutability remain isolated. Approximately 50 ms work slices publish partial
frames and continue from the next occurrence. Failed scripts do not halt healthy
instances, including when the failure occurs in the last slice. An EOF/late result
cannot leave the reader blocked while the parent disposes a failed worker.

Final local probes, with the same 56 authored cuboids and a script adding one
segment, reproduced the old aggregate error after 2,218.73 ms with only seven
completed instances. The revised full IPC/core pipeline completed all 56 in
260.09 ms cold and 238.48/231.93/227.13 ms on subsequent sweeps, preserving every
instance's initializer/state and its 12 triangles/13 segments. These are full
script update timings, not renderer frame rates. A separate helper-only probe
with 336 scene drawables improved from a 626.60 ms median to 78.50 ms; a larger
5,376-drawable snapshot completed in 298.13 ms median without querying the scene.

A 224-invocation native-helper probe measured RSS from 34,624 KiB initially to
51,688 KiB finally, with a 51,728 KiB observed peak. Infinite-loop and exception
requests were followed by successful queries in the same helper, confirming VM
recovery preserves its scene snapshot. These are bounded Linux observations,
not platform-wide timing or memory guarantees.

The isolated Xvfb/software-GPU GUI loaded 56 instances with 728 generated/authored
segments, opened the script editor, previewed and saved a second segment, and
updated all 56 instances to **784 segments / 672 faces**, without a timeout banner.
[56 instances after editing the prototype script](../references/scripted-objects/56-instances.png).
The new tests cover a forced 64-slice continuation, 56 instances through the real
engine across two sweeps, independent initialization/state, fresh globals, lazy
scene access and failed-instance scheduling. Final workspace tests, strict Clippy,
native build, formatting, eight packaging checks and the plan verifier pass.

## 0.9.0 — Construction and transform SDK

Added optional-ID rectangle/cuboid/polyline/circle constructors (circle resolution
12 by default), immutable nested point/drawable translate/rotate/scale transforms,
mirror/matrix transforms, ID-prefixing for copies, cylinders, planar concave
polygons, indexed polyhedra, extrusion and color helpers. Vector, degree
trigonometric, scalar/list/type functions, lookup and seeded random lists are
listed in Ctrl+Space. Ordinary JS remains available; this does not execute OpenSCAD
source or introduce its CSG/file-import language. The reference and supported
signatures are recorded in the SDK specification.

Desktop unit tests pass 260 regular tests (two opt-in probes ignored), including
non-mutating origin/axis rotation, reflections/copies with distinct IDs, default
constructors, concave triangulation, extrusion, material alpha and deterministic
random values. Strict workspace Clippy and the native build pass. The existing
script isolation/limits/state tests also pass.

## 0.15.0 — JavaScript/API highlighting and hover help

The native unified editor registers a JavaScript-only Tree-sitter grammar and
uses the shared completion/MCP catalog for constructor, function and field
highlight rules. Keywords, strings, comments and numbers have distinct colors.
The local hover provider resolves the symbol under the pointer and shows its
signature, description and example, including spaced member access and
`instance` aliases. Strings/comments/regexes are excluded; template expression
code remains eligible. Assistance is syntax/name based, without scope inference.

The pinned gpui-component 0.5.1 source is vendored with its Apache-2.0 license and
patch notes. Its Tree-sitter text provider skipped the first rope chunk and did
not clip text to a node. Using a sliced chunk iterator fixes name predicates;
regression checks assert actual rendered styles in short and multi-chunk scripts.

Validation on Linux:

- `cargo clippy --workspace --all-targets -- -D warnings`: passed for workspace
  targets; the vendored dependency emits eight existing deprecation warnings.

  `python3 docs/rewrite/scripts/verify_plan.py`: passed.
- Isolated Xvfb/software-GPU UI: opened a new object script, observed keyword/API
  colors, hovered `Point` and `this.geometry`, cleared help over a comment, and
