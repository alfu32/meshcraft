# T09 handoff

Status: in progress. Open, Save, Save As, dirty-document replacement, and debounced autosave use the desktop command registry; recovery remains open.

`File > Open Project…` and `Ctrl+O` use a cancellable worker reader with progress, 512 MiB encoded/decoded limits, candidate validation, and revision-guarded publication. Save and Save As serialize immutable snapshots on a worker, write schema 17 JSON/gzip through a synced same-directory temporary file, and track the exact saved revision. Typed payloads accept `path`; native dialogs are the fallback. Edits made during a save remain dirty.

Dirty Open/New requests show Save, Discard, and Cancel. The active document remains published until the user decides. Save continues replacement only after the saved revision still matches; newer edits trigger another decision. Failed or cancelled saves preserve the replacement prompt. Cancel keeps the document unchanged. Clean saves retain imported opaque undo history; dirty saves omit stale legacy snapshots and report that omission. Named documents now autosave 1.5 seconds after the latest document revision; untitled documents do not write implicitly. Edits during an in-flight save schedule a follow-up save when needed. Recovery backups, browser storage, and Kotlin reopen checks remain open.

Checks: `cargo test --workspace --quiet` passes (205 core, 193 desktop, 15 IO, 5 CLI). Autosave tests use a controllable clock to verify debounce reset and prevent implicit writes for untitled documents. A replacement-stage failure injection confirms the prior project remains byte-for-byte intact and the temporary file is removed. Existing tests cover dirty Open cancellation, New discard, Save continuation, newer edits during save, and failed-save preservation. All-target Clippy, desktop WASM check, formatting, plan validation, and diff whitespace checks pass. Native dialogs were not manually exercised.

## Native Recent Files submenu and safe replacement — 0.22.0 (2026-10-21)

The GPUI File menu uses the vendored component library's PopupMenu with a real
Recent Files child menu. It lists at most ten paths, newest first, with both file
name and path to distinguish duplicate names. An empty history has a disabled
explanation. Hover/Right opens the child; arrows and Enter select entries.
Selection dispatches `file.open` with the exact path, preserving the shared
asynchronous loader, failed-load behavior and unsaved-change decision. Popup
scroll input does not reach the canvas. Native history persists immediately after
successful opens, including successful command-line startup opens; failures to
write preferences remain diagnostics and do not reject a valid opened project.

Native unsaved replacement now has a GPUI Save/Discard/Cancel modal, using the
existing session decisions; it blocks canvas input and Escape cancels. During
isolated native validation, New was observed retaining the previous save path.
New now clears that destination/autosave deadline and marks the empty document
clean, so edits in the untitled document cannot autosave over the old project.
A regression preserves the previous file bytes through that sequence.

Related navigation adjustments in this version set Ctrl-wheel to ×0.1 and
Alt-wheel to ×0.05 (Alt takes precedence). Guide commands, point placement and
previews use the complete displayed cursor basis rather than rebuilding a basis
from the snap normal. A line/midpoint regression checks all three axes exactly.
