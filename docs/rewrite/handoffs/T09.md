# T09 handoff

Status: in progress. Open, Save, Save As, and dirty-document replacement use the desktop command registry; autosave and recovery remain open.

`File > Open Project…` and `Ctrl+O` use a cancellable worker reader with progress, 512 MiB encoded/decoded limits, candidate validation, and revision-guarded publication. Save and Save As serialize immutable snapshots on a worker, write schema 17 JSON/gzip through a synced same-directory temporary file, and track the exact saved revision. Typed payloads accept `path`; native dialogs are the fallback. Edits made during a save remain dirty.

Dirty Open/New requests show Save, Discard, and Cancel. The active document remains published until the user decides. Save continues replacement only after the saved revision still matches; newer edits trigger another decision. Failed or cancelled saves preserve the replacement prompt. Cancel keeps the document unchanged. Clean saves retain imported opaque undo history; dirty saves omit stale legacy snapshots and report that omission. Browser storage, autosave, recovery backups, and Kotlin reopen checks remain open.
