# T74 — Hotspots as selected content

Status: **Complete**, 0.52.0 · C47. Request: `tasks/todo/hotspots-and-objects/task.md`.

## Delivered

- Transform tools, Move Copy, Rotate Copy, arrays and Copy/Paste accept hotspots. A copy of a hotspot
  and its geometry drives the copied geometry. A closed instance's hotspot transforms as that
  instance's value and can't be copied.
- Explode keeps hotspots in the parent with new IDs and rebound attachments, including nested
  children, and bakes a dragged instance's shape with its marker left where it shows.
- Make Object accepts objects, mesh, dimensions, text and hotspots together. Objects become children,
  and everything else becomes the new object's own content.
- Inside an open object, Escape cancels an active tool and stays in the object. A further Escape
  leaves it.
- A selected hotspot draws its reference point and highlights its attached geometry.
- Select Attached finds geometry the same way evaluation does, so it still works after the attached
  geometry moves.

## Validation

Evidence: [references/hotspot-objects](../references/hotspot-objects/), including
`native-validation.json`. `python3 scripts/verify_hotspot_objects.py` runs the real tools through the
command and pointer path over MCP in a private Xvfb display. `verify_hotspot_panel.py` still passes.
`hotspot_scope_tests` in `object_workflow.rs` cover the unit level. The release gate passes.

**Not exercised:** the full stress suite, and hotspots on imported legacy `.k3d` objects with aliased
attachments beyond unit coverage of the matching rule. Pointer input here is MCP world coordinates, so
clicking a marker with a real mouse before a transform wasn't repeated.
