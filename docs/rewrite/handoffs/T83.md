# T83 — Standard shaders and shader program management

Status: **Complete**, 0.59.0 · C56.

## Request

After writing a bump shader by hand, the owner asked for:

1. Standard materials `emboss.rough_texture` (the bump shader), `emboss.tiling` and
   `emboss.rough_tiling` (both combined).
2. One New Material command where the shader is picked, instead of New Foliage,
   New Wood, New Water and so on, with a New Shader button next to the shader list.
3. Shaders for metal with hard reflections, glass, and classic Perlin noise if not
   too heavy.
4. A Shader Programs panel to manage programs like objects and materials;
   deleting a program should turn the materials that use it into standard ones.

## Behaviour

| Point | Decision | Reason |
| --- | --- | --- |
| IDs | The owner's names as IDs: `emboss.rough_texture`, `emboss.tiling`, `emboss.rough_tiling`; plus `metal.polished`, `glass.clear`, `noise.perlin` | Visible in the Program list and over MCP |
| Kind | Built-in surface programs, read-only like the presets | Edits store a copy; documents never carry their source |
| Relief | Derivative bump mapping (`patternBump`), shading only | Works on any triangles and transformed instances, no tangents |
| Metal and glass | New optional `proceduralLighting(lit, color, position, normal)` hook after scene lighting; procedural studio environment (sky, two light strips, horizon, ground, the scene light as a sun) | A mirror must not be multiplied by diffuse lighting; there is no environment map to sample |
| Smooth corner normals | Surface triangles carry per-corner normals averaged within 40° | The first capture showed every facet of a sphere in the reflection; box edges stay sharp |
| Perlin noise | Gustavson's texture-free classic 3D noise, 1–8 octaves (default 4) | One evaluation per octave; relief doubles it and is off by default |
| New Material | Program list by name; a built-in applies its suggested name (if untouched), colour and PBR to an unsaved material | One command replaces five |
| Old buttons | Removed from menus, ribbon and panels; IDs `material.new_grass` … kept | MCP clients, tutorial recipes and scripts keep working |
| New Shader… | Opens the shader editor on surface starters over the material editor; Save returns with the program chosen | The existing return-to-material path of Edit Program |
| Panel | Custom programs first, then built-ins, each with ID, kind and users; New Shader, New Shader Object, Edit, Delete | Mirrors the prototype and material lists |
| Delete | One Undo step; materials become conventional and keep colour, texture and PBR; the status names them | As requested |
| Delete refusals | Built-ins; programs shader objects still use, with the count | A shader object has no geometry without its program |
| Bake | Colour hooks run per vertex with `dFdx`/`dFdy`/`fwidth` reading as zero and `eye`/`towardLight` declared | The owner's hand-written bump box used `dFdx`, which failed to compile in the bake capture |

## Validation

`python3 scripts/verify_shader_library.py` passed **all 18 checks** in a private
1280×900 software-GL desktop, writing screenshots and `observations.json` to
[references/shader-library](../references/shader-library/). It covers:

- the five old buttons gone from menus with their IDs kept;
- Materials › Shader Programs holding the panel, New Shader, Edit and Delete;
- all six shaders on boxes and spheres with no diagnostics;
- polished metal's bright reflections and dark mirrored ground, measured in pixels;
- New Material › Program › Polished metal saving a metal material with that name, colour and metallic 1;
- New Shader… saving `custom.surface.1` and returning to the material with it chosen;
- Edit on a built-in, with Escape leaving it unchanged;
- delete making the material conventional and naming it, with a single Undo restoring both;
- built-in and shader-object programs refused.

Unit tests: deletion, refusals and library validity (`management.rs`); smooth corner
normals on a 20° fold and a box (`gpui_procedural.rs`).

GPU tests under `LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a`, `--ignored --test-threads=1 gpu_`:
**13 passed**, including the new `gpu_bake_custom_object_with_fragment_only_code`
and the existing brick, wood, water and foliage preset tests under smooth normals.

Release gate passed: `cargo fmt --all --check`; `cargo test --workspace --locked`
(**847 passed, 25 ignored**, no failures; the toolbar catalog test now expects
New Material in the Materials group instead of New Wood); `cargo clippy --workspace
--all-targets --locked -- -D warnings` clean.

Python: stress (17), release (19, 3 skipped), tool inventory (4) and tool icon (3)
suites passed; `export_tool_inventory.py --check` and `design_tool_icons.py --check`
report no drift (296 commands); `verify_plan.py` is valid (84 tasks).

`python3 scripts/stress/run.py --tiers small --samples 1 --only` over the ten
affected commands: `program.edit`, `program.delete`, `view.panel.programs.toggle`,
`material.new_shader`, `material.save`, `material.apply` and `material.program`
passed. `material.new`, `material.new_wood` and `material.new_grass` fail with
"viewport rendering is pending" while the material editor's preview is open. The
released 0.58.0 binary, run with the 0.58.0 harness, fails the same three commands
the same way, so this predates T83; it is recorded here, not fixed.

## Not verified

Hardware GL drivers were not tested; only Mesa software GL. Reflections show a
built-in environment, not other objects; glass doesn't refract. Pixel checks cover
metal only; the other shaders are checked for compiling, drawing and by screenshot.
